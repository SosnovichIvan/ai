# Как обновить Agent Foundry

Обновление Agent Foundry не удаляет ваши задачи, шаблоны, блоки задач, rules или
skills. Перед изменением данных приложение создаёт локальную резервную копию.
Для обновления не нужны Bun, Node.js, Rust или терминал.

## Перед обновлением

1. Завершите важные изменения в открытой задаче и дождитесь сообщения о
   сохранении.
2. Закройте Agent Foundry.
3. На странице релизов выберите версию для своей операционной системы.
4. Прочитайте разделы «Добавлено», «Изменено», «Исправлено», «Безопасность» и
   «Известные ограничения».

Если вы используете несколько компьютеров, обновление на одном из них не
синхронизирует данные с другими устройствами: Agent Foundry хранит их локально.

## Установка обновления

1. Скачайте файл только по ссылке со страницы релизов Agent Foundry.
2. Убедитесь, что платформа и архитектура совпадают с вашим устройством,
   например macOS Apple Silicon или Windows x64.
3. При необходимости сравните SHA-256 скачанного файла со значением на странице
   релиза. Если checksum не совпадает, не устанавливайте файл и скачайте его
   заново.
4. Откройте установщик или приложение и замените предыдущую версию согласно
   инструкции вашей операционной системы.
5. Запустите Agent Foundry. Если версия требует миграции локальных данных,
   приложение выполнит её до открытия рабочего пространства.

## Что сохраняется

Обновление сохраняет:

- задачи, их текст, название, описание, дату и revision;
- шаблоны, включая независимые снимки задач;
- блоки задач и снимки блоков, уже вставленные в задачи;
- выбранные и импортированные rules/skills;
- ваши правки существующих rules/skills.

Совместимое обновление может добавить новые встроенные rules и skills, но не
перезаписывает ваши изменения и импортированные материалы.

## Если обновление не завершилось

Не удаляйте приложение и не очищайте его данные. Перед миграцией Agent Foundry
создаёт резервную копию базы. Если `state-manifest.json` повреждён, не
согласован с базой или относится к более новой версии приложения, Agent Foundry
останавливает изменяющие операции: данные не перезаписываются автоматически.

1. Закройте приложение.
2. Сохраните сообщение об ошибке и путь к backup. Не редактируйте manifest
   вручную.
3. Повторно скачайте файл обновления со страницы релиза и убедитесь, что
   checksum совпадает.
4. Запустите обновление ещё раз.
5. Если ошибка повторяется, восстановите последнюю резервную копию, созданную
   до обновления, и обратитесь в поддержку. Приложите версию
   приложения, версию, на которую выполняется обновление, и текст ошибки. Не
   отправляйте `.env`, токены, cookies, ключи или содержимое приватных файлов.

## Возврат на старую версию

Не устанавливайте старую версию поверх данных, уже обновлённых новой версией:
это может быть несовместимо. Если нужно вернуться назад, сначала восстановите
backup, созданный до миграции, затем установите предыдущую поддерживаемую
версию. На странице каждого релиза будет указана минимальная поддерживаемая
предыдущая версия.

## Как выбрать версию

Обычно выбирайте последнюю версию канала **Stable**. Версии **Beta** предназначены
для ранней проверки новых возможностей и могут содержать известные ограничения.
Каждая карточка релиза показывает дату, изменения, поддерживаемые платформы,
checksum, подпись и доступные файлы.
