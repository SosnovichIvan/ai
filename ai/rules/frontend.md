# Правила frontend

## Перед началом

Для нового либо изменённого сценария прочитайте активный OpenSpec change и
утверждённый Figma node. Реализация включает desktop/mobile breakpoints,
loading, empty, error, disabled, hover и keyboard focus. Если нужного состояния
или компонента нет в дизайне, сначала согласуйте его, а не придумывайте локально.

## Архитектура и границы

Если проект использует Feature-Sliced Design, зависимости идут только сверху
вниз: `pages → widgets → features → entities → shared`. Страница отвечает за
композицию, а не за бизнес-логику, запросы или состояние. Фича имеет одну
пользовательскую ответственность; `entities` не содержат UI-фич, а `shared` не
зависит от верхних слоёв. В иной архитектуре сохраняйте тот же принцип:
направление зависимостей, публичные границы и одна ответственность на модуль.

## Код

- Один файл — одна сущность; имя файла отражает назначение и следует конвенции
  проекта. Компонент имеет PascalCase-имя, hook начинается с `use`, store и API
  имеют явно читаемое имя.
- Экспорт наружу идёт только через публичный API модуля (например, `index.ts`),
  без импортов во внутренности соседнего модуля.
- Props и типы описываются рядом с экспортом. Не дублируйте типы API вручную:
  используйте сгенерированный контракт либо единый доменный источник.
- Утилита выполняет одну операцию, имеет тест рядом и не скрывает I/O. Hook
  отделяет получение/преобразование состояния от представления.

## UI, состояние и доступность

Используйте существующую дизайн-систему и токены. Не создавайте копии базовых
кнопок, полей, loader, уведомлений и темы, если в проекте есть общий пакет.
Серверное и локальное состояние разделены; loading не показывает устаревший
интерактивный контент, ошибки объясняют дальнейшее действие. Для каждого
интерактивного элемента обязательны label, focus, управление с клавиатуры и
достаточный контраст.

## Проверка

Перед handoff выполните lint/typecheck, тесты изменённых utilities/hooks и
проверку сценария в целевых viewport. В diff не должно быть несогласованных
стилей, ручных DTO, обхода public API или неучтённых состояний.
