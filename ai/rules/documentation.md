# Правила документации

Документация отражает фактическое поведение, запуск, конфигурацию, ограничения,
безопасность и восстановление после ошибки. Current spec хранит реализованную
capability, change — историю намерения и решений, README/service docs —
архитектурный и operational context, а contract/Figma остаются отдельными
нормативными источниками.

Обновляйте документацию вместе с изменением интерфейса, контракта, данных или
процесса. Не описывайте план как поставленное поведение, не дублируйте схемы и
layout в нескольких источниках и не архивируйте change, пока docs не совпадают
с результатом проверки.
