# Правила работы с Git

Один change связывается с одной задачей и понятной веткой. Изменяйте только
относящиеся к ней файлы, сохраняйте чужие незавершённые правки и передавайте
читаемый diff. Commit сообщает результат задачи, а не набор файлов; перед ним
проверьте status, staged diff и отсутствие секретов/артефактов.

Не делайте `reset --hard`, массовое удаление, переписывание чужой ветки, push,
merge или rebase без явного разрешения. Не полагайтесь на ветку `main/develop`
как универсальное правило: следуйте конвенции конкретного проекта.
