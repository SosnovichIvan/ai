# Базовые правила агентной работы

## Источники истины

- `openspec/specs/` описывает текущее реализованное поведение.
- `openspec/changes/<change>/` описывает предлагаемое изменение до архивации.
- `AGENTS.md` задаёт правила конкретного проекта.
- `ai/` данного репозитория — источник устанавливаемых общих правил и skills.

При конфликте приоритет имеют явный запрос пользователя, правила целевого
проекта и более строгое требование безопасности.

## Рабочий цикл

1. Изучить текущие specs, активный change и близкую к задаче документацию.
2. Для нового поведения создать OpenSpec change и сформировать proposal, delta
   specs, technical design и проверяемые tasks.
3. Выполнять работу только после прохождения необходимых gates.
4. Проверить результат, синхронизировать current specs и архивировать change.

## Definition of Done

- Поведение описано проверяемыми requirements и scenarios.
- Каждая задача содержит способ проверки.
- Проверки выполнены и их результат известен.
- Не внесены несвязанные изменения.
