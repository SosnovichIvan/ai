# Жизненный цикл изменений

Любое новое или изменяемое поведение проходит SDD: прочитать current specs,
создать change с Why/From-To/scope/non-goals/версией, описать delta requirements
с WHEN/THEN, design, risks, rollback и проверяемые tasks. Current spec описывает
реализованное поведение, change — только предлагаемое; не смешивайте их.

Для UI до реализации нужен Figma URL с node-id и явный `APPROVED`: основной
сценарий, error/empty/loading, интерактивные состояния и relevant viewport.
Если действие не имеет визуального поведения, зафиксируйте `NOT_REQUIRED` с
конкретным анализом scope. Изменение дизайна после approval требует новой версии
и подтверждения, а не незаметной правки старой.

После реализации выполните проверки каждого task, verify, обновление current
specs и archive. Нельзя отмечать task без доказательства, архивировать change с
незавершёнными пунктами или продолжать при конфликте нормативных источников.
