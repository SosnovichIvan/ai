# Стратегия качества

Определите минимальную тестовую пирамиду для изменения: unit для алгоритма,
integration для инфраструктурной границы, contract для публичной схемы и E2E
для критического пользовательского пути. Риск потери данных, авторизации,
совместимости и поставки требует отдельного сценария, а не только покрытия строк.

Планируйте воспроизводимые fixtures, контролируемые часы/сеть и чистый запуск
CI. Анализируйте flaky tests как дефект сигнала. Перед release проверьте
наблюдаемость, rollback и фактическое прохождение сценария; в отчёте различайте
пройденные проверки, известные ограничения и остаточный риск.
