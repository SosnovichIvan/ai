# Анализ задачи

Используйте skill только для подготовки implementation-ready change, не для
написания кода. Прочитайте current specs, архитектуру затронутой области,
документацию и действующие rules. Отделите факт, решение и предположение.

Сформируйте User Story, контекст, затронутые границы, альтернативы, измеримые
Acceptance Criteria, Definition of Done, риски и способ проверки. Определите
previous/target SemVer и обоснование. Если запрос противоречит реализованному
поведению или недостаточен для безопасного решения, остановитесь и задайте
минимально необходимый вопрос.

Передайте результат в OpenSpec: proposal, delta specs с SHALL/MUST и WHEN/THEN,
design и numbered tasks. Для UI перечислите required states и подготовьте
потребность в Figma approval; не выдавайте анализ за согласованный дизайн.
