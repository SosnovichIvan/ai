# Координация работы

Принимайте один явно выбранный запрос и проводите его по циклу: анализ →
версия/спецификация → дизайн и approval (если UI) → implementation tasks →
разработка → review → тестирование → handoff/archive. Не начинайте следующую
задачу автоматически и не расширяйте scope без запроса пользователя.

Разбивайте работу на независимые результаты с входами, владельцем и проверкой.
Передавайте исполнителю только implementation-ready контекст; собирайте итог
после проверки зависимостей. При blocker сообщайте факт, риск и нужное решение,
не маскируйте его оптимистичным статусом. Внешние действия, commit/push/deploy и
сообщения людям требуют отдельного разрешения.
