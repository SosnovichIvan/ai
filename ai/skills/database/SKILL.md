# Изменения данных

Начните с владельца данных, инвариантов, read/write paths и объёма. Спроектируйте
ключи, ограничения, индексы и migration sequence так, чтобы старая и новая
версия приложения могли сосуществовать. Для backfill задайте batching, resume и
наблюдаемость; destructive step откладывайте до завершения миграции потребителей.

Проверьте план запросов и transaction boundaries. Кэш имеет TTL и invalidation;
очередь/объектное хранилище не маскируют отсутствие source-of-truth. Не берите
production dump для фикстур, не логируйте значения чувствительных колонок.
