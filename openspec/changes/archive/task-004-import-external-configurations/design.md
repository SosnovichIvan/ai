## Context

Пользователь должен видеть не демонстрационный список, а действующий набор
правил и skills. Внешние директории могут быть неполными, содержать несколько
форматов либо чувствительные файлы. Поэтому анализ отделён от импорта, а запись
в активный каталог происходит только после понятного preview и явного выбора.

## Goals / Non-Goals

**Goals:** безопасно находить переносимые документы, прозрачно показывать
результат, сохранять выбор пользователя и делать replace обратимым.

**Non-Goals:** запуск найденного кода, универсальный парсер каждого формата
агентных инструкций и скрытая модификация целевого проекта.

## Approved UI flow

Экран Figma `51:62` добавляет в Environment:

1. кнопку `Анализировать папку` рядом с другими действиями заголовка;
2. системный folder picker без ручного ввода пути;
3. результат анализа с количеством rules и skills, исключёнными секретами и
   списком найденных относительных путей;
4. два взаимоисключающих режима: `Добавить` выбран по умолчанию и `Заменить`;
5. переход к preview. Для `Заменить` в preview требуется отдельное
   confirmation с названием заменяемого набора и датой backup.

## Decisions

### Runtime catalog and seed

- `ai/` в репозитории остаётся единственным версионируемым authoring source.
- При первом запуске приложение копирует bundled `ai/` в app-data runtime
  catalog с версией seed. Редактор и импорт работают с runtime catalog, а не со
  статическими строками UI.
- Каждая import transaction хранит source root только в локальном manifest;
  пользователь может увидеть его, но приложение не отправляет его наружу.

### Discoverable files

- Scanner рекурсивно обходит только выбранный root и не следует symlink.
- Допустимые skills — файлы с точным именем `SKILL.md` в папках skills;
  допустимые rules — Markdown-файлы внутри папок rules/instructions.
- До открытия файла scanner исключает `.env`, `.env.*`, private keys,
  credentials, cookies, token files, `.git`, `node_modules`, `target`, `dist`
  и другие технические каталоги. Исключения учитываются только счётчиком, без
  имени или содержимого секрета в UI/логах.
- Каждый candidate получает category, относительный путь, размер и content hash.
  Содержимое открывается для preview только после прохождения allowlist.

### Add, replace and conflicts

- `Добавить` создаёт в runtime catalog только новые управляемые пути. Совпадение
  пути с отличающимся hash остаётся конфликтом и не перезаписывается.
- `Заменить` формирует полный managed set из результата анализа, создаёт
  timestamped backup активного runtime catalog, а затем атомарно заменяет его.
- Оба режима сначала строят immutable import preview; commit принимается только
  с идентификатором preview, чтобы результат сканирования нельзя было подменить
  изменением файлов между analyse и apply.

### Atomicity and rollback

- Копирование происходит через staging folder в app-data на том же volume.
- Commit сначала проверяет hash всех candidates, затем выполняет atomic rename
  runtime catalog и записывает manifest последним.
- При ошибке прежний каталог возвращается из staging/backup. Повреждённый
  manifest блокирует commit и предлагает восстановить последнюю backup.

### IPC and UI stability

- Frontend передаёт только typed session/preview identifiers, выбранный core
  path и import mode; arbitrary read/write path commands отсутствуют.
- Выбор файла в `SourceEditor` сбрасывается на первый существующий файл при
  смене категории и каждый read проверяет границы списка. Это исключает crash,
  когда количество skills и rules различается.

## Alternatives considered

- **Прямо редактировать bundled `ai/`:** не работает для signed/read-only
  пакетов и разрушает separation между release seed и пользовательским state.
- **Импортировать сразу после выбора папки:** пользователь не видит конфликты и
  не может выбрать режим, поэтому отклонено.
- **Автоматически сливать совпадающие Markdown:** невозможно надёжно сохранить
  смысл инструкций; конфликт требует действия пользователя.

## Risks / Trade-offs

- Внешние репозитории различаются по структуре, поэтому MVP ограничен
  прозрачным allowlist; нераспознанные файлы будут показаны как пропущенные,
  без чтения содержимого.
- Runtime copy добавляет миграцию каталога, но делает desktop package реально
  редактируемым и не ослабляет версионируемый `ai/` как release seed.
- Replace мощнее add, поэтому требует отдельного confirmation и backup.
