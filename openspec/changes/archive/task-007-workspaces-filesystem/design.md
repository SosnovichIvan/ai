## Информационная архитектура

Вверху рабочего раздела расположен selector Workspace и кнопка «Создать
рабочее пространство». Под ним — breadcrumb текущей папки и переключатель
режимов: дерево раскрыто слева либо пользователь вошёл в папку и видит только
её содержимое.

Каждая сущность хранится в одном Workspace. Папка — отдельная сущность с
`parentId`, поэтому дерево едино для задач, шаблонов, блоков, rules и skills.
Перемещение и share — copy-by-default: цель получает независимую копию.

Удаление Workspace и папок требует preview количества вложенных элементов и
отдельного confirmation. Default Workspace удалить нельзя.

## Design gate

До UI-реализации необходимы Figma frames с node-id: пустое Workspace,
создание Workspace, tree expanded, folder focus, share dialog, confirmation
удаления и desktop/tablet/mobile variants.

## Миграция и откат

При первом запуске схема локальной базы обновляется до версии 2. До миграции
существующего файла `ai-works.sqlite3` создаётся рядом резервная копия с
суффиксом `backup-<timestamp>`. Все ранее созданные задачи, шаблоны и блоки
получают `workspaceId = default` и `folderId = null`; создаётся Workspace
«Моё рабочее пространство». Миграция выполняется одной SQLite-транзакцией:
при ошибке версия схемы не меняется и исходные данные остаются доступными.

Откат до предыдущей версии выполняется только вручную: приложение должно
быть закрыто, текущий файл базы сохранён отдельно, затем резервная копия
переименовывается обратно в `ai-works.sqlite3`. Новая версия не удаляет
сохранённые каталоги rules/skills: старый каталог считается содержимым
`default` Workspace, а каталоги новых Workspace хранятся изолированно.

Регрессия проверяет: перенос legacy-record в default Workspace, изоляцию
списков по Workspace и папке, независимость копии при share, запрет удаления
default Workspace и отсутствие bundle rules/skills в новом каталоге.
