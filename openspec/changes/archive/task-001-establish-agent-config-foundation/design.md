## Context

Анализ `my-sport-life`, `relayform` и `arhdesign` показал полезные практики:
OpenSpec lifecycle, разделение project rules/context/skills и локальный формат
`SKILL.md`. Полный реестр материалов и решений о переносимости зафиксирован в
`ai/source-analysis.md`. Их проектно-специфичные правила нельзя переносить как
общие.

## Goals / Non-Goals

**Goals:** создать минимальную, переносимую и расширяемую основу.

**Non-Goals:** копировать продуктовые стеки, Figma-правила или жёсткие git
конвенции других репозиториев.

## Decisions

- `ai/` — source of truth; `catalog.yaml` — декларация профилей и mapping.
- Общие правила укладываются в `AGENTS.md` целевого проекта, skills — в
  `.agents/skills/`, что совместимо с уже используемым локальным layout.
- Будущий UI вызывает независимое безопасное ядро. Это надёжнее browser-only
  реализации, которой недоступна полноценная файловая система.
- Конечный пользователь получает собранный нативный пакет; Bun, Node.js и Rust
  остаются только инструментами сборки для команды разработки и не являются
  runtime-зависимостями пользователя.
- Будущий конструктор задач использует versioned templates из `ai/templates/`.
  Задача хранит template ID, версию, валидированные параметры и результат;
  шаблон не исполняется как код.

## Security and Atomicity

Preview до записи, target-bound path validation, conflict-by-default, backups,
atomic writes и manifest after success являются обязательными инвариантами.

## Rollout / Rollback

Основа не меняет другие проекты. Будущая установка создаёт backups в target,
которые позволят вернуть заменённые управляемые файлы.

## Risks / Trade-offs

Копии в target могут устареть; manifest и повторный preview позволяют выявить
это до обновления. UI требует отдельного утверждённого дизайна. Формат шаблонов
требует отдельного change, чтобы не смешивать предметную модель задач с
инфраструктурной основой.
