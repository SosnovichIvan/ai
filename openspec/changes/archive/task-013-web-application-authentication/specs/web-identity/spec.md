## ADDED Requirements

### Requirement: Регистрация по уникальному логину

Система SHALL принимать при регистрации логин, пароль и подтверждение пароля.
Логин MUST быть уникален без учёта регистра, а создание пользователя и его
default Workspace MUST происходить атомарно.

#### Scenario: Регистрация со свободным логином

- **WHEN** пользователь передаёт валидный свободный логин и совпадающие пароли
- **THEN** система создаёт пользователя, сохраняет только password hash и
  открывает его авторизованную сессию

#### Scenario: Занятый логин или несовпадающие пароли

- **WHEN** пользователь передаёт уже занятый логин либо разные пароль и
  подтверждение
- **THEN** система не создаёт пользователя и возвращает понятную ошибку поля

### Requirement: Вход и выход

Система SHALL принимать существующие логин и пароль, создавать защищённую
server-side сессию и позволять пользователю завершить её.

#### Scenario: Успешный вход

- **WHEN** пользователь передаёт корректные логин и пароль
- **THEN** система создаёт `HttpOnly` session cookie и предоставляет доступ
  только к данным этого пользователя

#### Scenario: Выход

- **WHEN** авторизованный пользователь выбирает «Выйти»
- **THEN** server-side сессия инвалидируется, cookie очищается и клиент
  возвращается на страницу входа

### Requirement: Изоляция пользовательских данных

Система MUST проверять session на каждом защищённом запросе и MUST отклонять
доступ к сущностям другого пользователя.

#### Scenario: Запрос без сессии

- **WHEN** клиент обращается к защищённому API без действующей сессии
- **THEN** система отвечает `401` без внутренних деталей

### Requirement: Явный импорт legacy-данных

Система SHALL принимать только валидный export-формат legacy state после
явного действия авторизованного пользователя. Импорт MUST создавать Workspace,
Folder, Task, Template и TaskBlock в одной transaction и MUST откатиться без
частичного состояния при любой ошибке.

#### Scenario: Успешный импорт export-файла

- **WHEN** авторизованный пользователь подтверждает валидный legacy export
- **THEN** система создаёт независимые записи пользователя и возвращает их
  количество по категориям

#### Scenario: Некорректный export-файл

- **WHEN** export не проходит schema validation или содержит несогласованные
  ссылки Workspace/Folder
- **THEN** система отклоняет import до записи и не изменяет существующие данные
