## Контекст

UI не меняется: дизайн-утверждение не требуется. До любого изменения данных
desktop backend сверяет компактный manifest состояния с поддерживаемыми
версиями SQLite и каталога.

## Формат состояния

В app-data хранится `state-manifest.json`:

```json
{
  "version": 1,
  "sqliteSchemaVersion": 2,
  "catalogVersion": 2,
  "updatedAt": 0
}
```

Manifest содержит только версии и timestamp, не пользовательский контент. Его
запись выполняется атомарно через временный файл и rename. Отсутствующий
manifest допустим для существующей v1.0.0 базы: приложение сначала проверяет
фактические версии, затем создаёт manifest.

## Совместимость и recovery

Реестр миграций — единственное место, где объявляются поддерживаемые номера
SQLite-схем. Перед миграцией создаётся backup базы. Если schema или manifest
новее приложения, если manifest повреждён или не согласован с диском, backend
возвращает безопасную ошибку и не вызывает мутацию. Исходные данные остаются
нетронутыми; пользователю доступен путь к app-data и backup для ручного
восстановления.

При rollback бинарника downgrade данных не выполняется. Пользователь
восстанавливает backup, созданный перед обновлением, либо возвращается к
совместимой версии приложения.

## Регрессия

Тесты покрывают: fresh state, существующую v1.0.0 базу без manifest,
совместимый manifest, более новый manifest, повреждённый manifest и rollback
при ошибке миграции. Проверка regression гарантирует, что Task, Template,
TaskBlock, Workspace и Folder сохраняются без потери содержимого.
