## Context

Пользователь задал паттерн, близкий к VS Code/IDE: постоянная боковая панель
организует продукт по рабочим областям, а центральная область показывает
выбранную задачу. Первая область — установка окружения; вторая — задачи и
шаблоны.

## Goals / Non-Goals

**Goals:** быстрый переход между двумя основными работами, видимое активное
состояние, ясный путь от выбора папки к безопасной установке, основа для
будущего создания задач из templates.

**Non-Goals:** копировать VS Code визуально или перегружать MVP второстепенными
панелями IDE.

## Decisions

- Единственная навигация находится в блоке `AI Works` слева и содержит два
  верхнеуровневых пункта: «Установка окружения» и «Задачи и шаблоны». Отдельный
  icon rail не используется.
- Активная рабочая область внутри `AI Works` выделяется полужирным текстом, а
  неактивная — пониженной контрастностью.
- «Установка окружения» открывает workflow: target folder → profile → preview
  → conflicts → apply → result.
- «Задачи и шаблоны» открывает список задач, список templates и действие
  «Создать задачу»; на первом экране показывается пустое состояние, пока
  локальные данные отсутствуют.
- Центральная область использует заголовок выбранной рабочей области, сохраняя
  IDE-подобную иерархию без имитации лишних функций редактора кода.
- Основные действия располагаются справа в строке заголовка: выбор папки и
  применение профиля — для установки; создание задачи — для задач и templates.
- Путь не вводится вручную: действие `Выбрать папку` открывает нативный dialog
  ОС. После выбора интерфейс показывает нормализованный путь как read-only
  данные, переименовывает действие в `Изменить папку` и делает apply доступным.
- Внутри рабочей области используются локальные вкладки `Установка`, `Skills` и
  `Rules`; они не создают новую глобальную навигацию.
- Установка показывает стадии, текущую операцию, процент и безопасный итог
  (`completed`, `conflict` или `failed`). Skills и rules открываются как текст с
  редактором, проверкой несохранённых правок и явным сохранением.
- Модуль задач размещается на отдельной Figma Page. Внутри него локальные
  сегменты `Задачи`, `Шаблоны` и `Блоки задач`. Редактор задачи содержит
  текстовую область и правую панель пользовательских мини-шаблонов: нажатие на
  блок вставляет его текст в положение курсора. Задачу можно сохранить как
  template, после чего она становится доступна в сегменте `Шаблоны`.
- Панель блоков явно маркируется как `Вставить в курсор`; каждый блок в ней
  представлен компактной карточкой с названием и минимальным описанием, чтобы
  пользователь понимал содержимое вставки до нажатия.
- Длинные списки задач, templates и блоков отображаются компактными карточками:
  обязательное название, необязательное описание и локальные действия
  `Редактировать` / `Удалить`. Создание каждой сущности выполняется в отдельной
  форме; `Название` обязательно, `Описание` опционально.

## Figma Discovery

- Исходный canvas был пустым: `Page 1` (`0:1`), поэтому Code Connect и анализ
  существующих экранов неприменимы.
- В file подключены `Material 3 Design Kit` и командная палитра. Для навигации
  используются Material 3 `Navigation Rail`, а для действий — `Button`;
  текстовые стили берутся из Material 3.
- Черновые desktop frames: environment `3:4`, tasks/templates `7:403`.
- Полный workflow установки: initial `3:4`, selected/ready `21:19`, progress

- Карточки добавлены в list screens; формы создания: задача `37:106`, template
  `37:154`, блок задачи `37:200`.

## Security and Atomicity

Экран установки всегда показывает preview до apply; конфликт не отображает
содержимое потенциально чувствительных файлов. UI не имеет прямого доступа к
файловой системе — он вызывает безопасное ядро.

## Rollout / Rollback

Дизайн создан как два отдельных Figma frames. Реализация начнётся только после
визуального ревью и явного подтверждения конкретного node-id пользователем.

## Risks / Trade-offs

IDE-метафора может сделать простой сценарий тяжёлым; поэтому rail содержит
только два режима, а рабочая область остаётся task-oriented.
